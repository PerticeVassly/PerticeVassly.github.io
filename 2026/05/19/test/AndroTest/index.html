安卓测试入门

本科毕设做的这个方向，简要记录一下入门的经过

OS

Ubuntu是必备，Windows下WSL存在嵌套虚拟化问题，由于需要启动具体的模拟器设备，性能极差。

安卓模拟器生态

包括如何启动一个安卓设备模拟器，参考资料 https://github.com/Yuanhong-Lan/DQT

通过Andro Studio GUI界面可以完成所有内容，在此不赘述，此外还可以通过命令行启动

首先安装Android SDK Command-Line Tools，具体安装方式为官网下载（https://developer.android.com/studio）

zip解压。然后按照android_sdk/cmdline-tools/{version}/bin/的方式调整一下目录结构(将cmdline-tools中所有产物多下移一层)。此处version可以直接用latest, 并将目录加入PATH环境变量，识别到sdkmanager即可

使用sdkmanager --list查看所有可用的包

我们需要一个build-tools，一个platforms，一个emulator和一个system-images。各自作用见官网.

具体版本自行选择，可以通过例如sdkmanager "build-tools;33.0.2" "platforms;android-33" "emulator" "system-images;android-33;google_apis;x86_64"的方式进行安装，之后android_sdk目录下回出现对应的软件包，注意将对应的目录加入PATH

在拥有镜像以后可以通过镜像创建设备，使用例如

其中-d的参数可以用avdmanager list devices查看, 表示具体的设备型号

随后可以使用emulator命令启动模拟器

emulator -avd Pixel_2_API_28 -skin 1080x1920 -memory 4096 -sdcard 1G [-gpu host]

其中-vmheap的配置目前已经无法在cmd中使用，可以在~/.android/avd/{Pixel_2_API_28.avd}/config.ini中进行修改 (vmheap字段)

-gpu 可能由于多层嵌套虚拟化等原因失效，此字段可以不开启

此时可以使用adb devices查看模拟器是否启动成功

最重要的工具是adb，adb能够支持模拟器和主机之间的文件传递，以及远程监控模拟器状态，调整设置。

包括adb shell cmd, adb shell svc, adb logcat, adb pull, adb shell dumpsys…

移动GUI测试

主要是用过生成用户图形界面输入进行测试，整个过程随机性较大、测试时间长，属于工作量比较大的方向，然后其计算资源需求又恰好处于个人pc能够完成的中间态…

具体工具的使用方法各不相同，相对比较一致的是结果评估方面。

异常检出率：这个主要是从logcat中提取，并且进行去重，归类，可以参考 https://github.com/Yuanhong-Lan/AndroTest24 中的过滤代码，但是不同工作的提取方式有所不同

代码覆盖率：这个需要自行编译插桩，具体可以参考 https://github.com/Yuanhong-Lan/Android-Jacoco-Instrumentation-Guide 其中插桩编译的过程尤其繁琐，耗费大量时间

实际做的过程中，需要处理模拟器不稳定等现象，此外对于检测出的缺陷，目前没有比较好的自动复现方式，最终进行缺陷复现的方式竟然还是录屏重放。

随着应用的鲁棒性越来越高，检出的异常数其实已经越来越少了，而且检出异常不等于发现缺陷，部分异常本身就是合理的（比如访问不存在host）

个人感觉（完全就是我浅薄的胡说八道），可能实际工业中的应用也比较有限？更多还是基于用户及时反馈+ 预发布等更加上层的方式来进行质量管理？ 现有的测试方法真的能处理实际业务中如此细粒度的问题吗？ 感觉有点大海捞针。
